# 原版复原清单

基线：`jyx-legacy-data` 的固定提交 `b41198219087858ece19d5484f5061e0289c47bc`。
规则与剧情统计不合并官方 Silverlight 早期版、上传的 X1.0.0.1 及其他 MOD 的差异；本次美术单独取自用户上传的 X1.0.0.1 包。
剧情段来自 `storys.xml`、`storysCG.xml`、`storysPY.xml`，包括扩展／调试段，不是主线章节数。此前上传包中另发现 78 段鹿鼎记记录，尚未与这套基线合并，不能算作已经接入。

## 完成度口径

以“主要原版流程可玩、规则经过对照、能完整存读档和通关验收”为目标。早期 40%～50% 是当时的工程粗估，不再作为当前测量值。现阶段没有完整规则覆盖与逐路线实玩分母，不能给出可信的精确总百分比，80% 仍须按验收清单推进。

可精确计算的结构数据：剧情 1,866 / 1,887 ≈ 98.9%，地图事件 1,113 / 1,120 ≈ 99.4%，世界触发 21 / 21，地图定义 162 / 162。以上只代表接入范围。实际验收已从开局扩大到正常成长、八人招募、“黑暗的阴影”“神秘剑客”和“组织”；后期内容仍需逐条验证。80% 目标的验收门槛另见 [目标清单](ORIGINAL_80_TARGET.md)，目前尚未达成。

## 已接入原版一周目人物生成

默认新游戏现在经过七组原问答、24 个原头像选择、基础属性预览和重摇，再确认进入出生剧情。姓名与三个现有难度保留现代浏览器表单。答案的属性、天赋授予、模型、银两和初始行囊读取独立内容配置，确认前不创建正式会话；重摇从角色模板重建，固定三次 +10 与十次 +1，确认时使用同一个候选人物。出身奖励是放入行囊，穿戴仍由玩家决定。

规则基线为固定 `jyx-legacy-dll` 的 `RollRoleUI.cs`：初始 100 两、3 颗小还丹，按答案调整；普通一周目另有 5 个新手礼包。商人、流浪汉等出身的最终银两不同。旧版本和 Lua 覆盖存在差异，本实现按该 C# 的十种属性均匀抽样，不声称复刻 Lua 中的零／一基下标问题。多周目／试炼继承物品已接入；无悔实时存档与 Lua 覆盖的随机初始伙伴仍未开放，新增天赋的授予不等于它的全部战斗效果已复原。

## 已接入原版美术

`jyx` 内容包改为读取用户上传 `X.rar` 中的原版地图、战斗背景、头像、物品图标与角色帧。162 张地图、394 场运行包战斗、347 件物品及 513 个角色的图片引用均已解析；这表示引用有图，不表示所有地点都已实玩。角色按各自定义读取模型和头像，不再写死南贤、木人或伙伴图片。当前角色运行态的外观变化也会反映到画面。

提取清单含 638 个原资源路径、123 个模型入口、479 组动作片段；入口与别名不能作为独立人物数。待机、移动、攻击和受击由现代战斗事件驱动，可暂停；原素材只负责显示，不运行 Unity EXE 或旧 DLL。原始哈希与来源见 [素材记录](public/art/legacy/README.md)，引用覆盖与缺口见构建输出 `data/legacy-art-coverage.json`。

## 人物管理与特殊玩法接入

人物面板可选择参战队友，真实分配升级属性点、穿卸装备、选择内功与秘籍修炼。
每本秘籍最多供一名角色同时修炼；参战角色在真实结算时获得对应修炼经验。
玩家主动转后备的角色保留同一个人物／装备实例，可存读档后召回。剧情安排的随行或离队角色
不能通过编队强行变为参战队员；剧情离队会撤销玩家召回资格，并按既有服务归还装备。
原松鼠旅馆箱子包含首次介绍与后续存取，容量、任务物品限制、装备实例和数量均由 ChestService 管理。

竞技场、天关、试炼、珍珑、洗练使用现有 Application 服务；浏览器提供必选／禁选／人数受限的
参战选择、实际战斗和结果回写。女主命名等待实际输入，姓名与随行状态可存读档。
同福客栈升级使用原 100 两／10 天费用与实际 LevelUp；洗练显示真实候选、消耗元宝，保存真实词条。
规则层测试包含原战斗数据与隔离高属性输入；额外木人对手用于稳定验证胜利回写，
明确不算原版 Boss 或整个后期章节通关。

同福客栈轻功与葵花点穴手已接入实际小游戏，保留原十两费用、月度冷却和
Application.MiniGameService 的奖励、唯一奖励标记、练习点与身法／臂力成长。
轻功沿用四个反弹头像、300 初速和每 0.2 秒加速 1%；碰撞结束。
点穴持续 30 秒，目标出现 0.7 秒，东／西／南／北分别 −2／+4／+2／+3 分，物品目标计实际点击。
模拟运行于独立 Presentation 状态；浏览器只发送开始、移动、点击、暂停及结束输入，
运行时根据自身时钟计算成绩，不接受网页提交的得分、时长或奖励清单。
显示尺寸按 1920×1080 逻辑场地缩放，支持触屏、鼠标和轻功方向键；隐藏页面自动暂停。
这复用当前仓库 Godot 小游戏的玩法参数，尚未与旧 Unity 程序逐帧对照。

## 华山、结局与周目衔接

华山连战调用现有 SpecialBattleService，按原四场配置选择参战者、禁止队友重复出场，
失败进入真正的 GameOver 并记录死亡；全胜继续原分支判断及结局对白。原普通难度入口仍按
原剧情选择简单战斗，未强行替换为困难模式四连战。
`gameFin`、重开、下一周目会暂停在独立结局界面。可保存／导出结局及继承记录，读回时
恢复结局状态，不把落幕当成普通地图，也不重复记录通关。确认周目人物前可取消预览。
确认后用 SessionFlowService 重建本轮状态，保留仓库、元宝、档案和装备编号序列，清空
旧队友、行囊、编队、修炼和剧情。原问答重新执行，按 `RollRoleUI.MakeZhoumuAndShilianBonus`
生成周目及上轮试炼物品；不会重复发放一周目礼包或额外叠加服务中的 100 两。
武学上限奖励的去重键按周目区分，兼容旧一周目键；Lua 专有初始伙伴尚未移植。

已有 17 项周目／新游戏服务测试通过，另有真实结局、重开、下一周目、冷启动读档和
浏览器窄屏检查。四场原华山战斗到 True Ending 使用隔离高属性及前置剧情记录验证，
不作为正常成长路线通关或原版 Boss 难度的证据。更长的连续主线仍须扩大实玩。

## 仍未完成

- **21 段剧情和 7 个地图事件被隔离**，含直接错误及其上游依赖。剩余缺口包括点穴互动、缺失地图和两个木人角色引用，以及原 XML 的空对白／缺少说话人问题。
- **剧情和世界没有全量实玩**。结构检查只证明已转换的指令及显式跳转引用闭合，不证明每个条件分支、角色在队前提、限时任务和后期战斗都符合原版。
- **战斗规则尚非原版全量等价**。首战补齐的规则见 [战斗对照](../Game.Web.Runtime/BATTLE_PARITY.md)；大量天赋／Buff 定义只有描述或部分规则，AI、行动条与随机序列也仍有差异。不能把导入定义数当作效果完成数。
- **系统界面仍有缺口**：无悔实时存档、Lua 初始伙伴、剩余特殊互动和完整剧情道具使用尚需逐项接入。已接入的特殊模式仍需扩大实际路线、难度及多轮奖励验证。
- **演出尚未全量复原**：原版静态美术和基本角色动作已接入。4 个角色引用的 `daxia` 模型在上传包中缺失，使用各自原头像；无模型定义的人物同样使用原头像。部分动作只能按原帧编号恢复顺序、以明确的默认帧率播放，尚非 Unity 时间线逐帧复刻；音频、完整技能特效和剧情演出仍待接入。原版时间／位置规则已使用现代 Core 实现，尚未与旧程序做逐帧或同种子回放对照。
