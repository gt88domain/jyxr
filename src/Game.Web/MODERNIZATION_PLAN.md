# 原版内容的现代化重制

用户已选择现代化重制。本计划是接下来的开发与验收依据；此前的原版迁移、90%阶段记录和规则差异继续保留，不能把历史百分比当作现代化版本的完成度。

## 内容边界

- 保留已接入的人物、剧情、地图、道具、武学、招募条件及原素材；保留伙伴图鉴、155条路线图及地图前置提示。基础数值暂不整体重平衡。
- 继续使用TypeScript/Phaser界面与C# WebAssembly规则内核，不运行旧DLL。旧资料只用于对照与导入。
- 当前有格子的集气战棋与手动、自动操作保留；无格子即时战斗属于另一个玩法设计，不在本阶段改造。
- 旧随机调用顺序、Unity粒子逐个复刻与已证实无实际玩法价值的旧缺陷不作为发布前提。伤害、保护、反弹、死亡和奖励必须有明确、一致、可验证的规则。
- 缺来源的双儿及两类木人、额外版本补充入口继续归档为可选内容，不为凑完整度猜造数据，也不删除已接入的后期伙伴池。不将双儿的NPC管理用途视为已查证事实。用户提到的V43.0暂不扩展，不在未确定对应内容前批量删除资料。
- 西方试验章保持现状，优先完成原版内容下的现代化体验。

## 必须继续解决的实际问题

- 正常26级队伍的最终战曾失败；需要先区分难度、成长路线与规则缺陷，不通过强改胜负或一律削弱敌人处理。
- 多目标、自伤、分伤、濒死与复活要确定现代规则下的顺序，避免错扣资源、重复奖励、死者继续行动或卡死。允许与旧代码不同，需说明影响。
- 缺来源的天赋效果不算已实现；需要设计时，单独记录为重制规则。剧情缺引用、隐藏时限及实际无法触发的路线继续排查。
- 无悔实时战斗/交互存档仍未实现，不能把普通自动存档称作无悔模式。

## M1实现说明

四种界面状态由当前队伍位置和已有的玩家后备资格计算，不新增存档格式：玩家安排后备与剧情离队仍走不同服务。每类显示人数、说明和适用操作，参战队员装备与武功详情可展开。剧情暂离仅表示目前不能由玩家召回，不保证将来一定重新加入。

本轮Release构建与类型检查通过。原生管理回归验证实际招募/随行、换装、修炼、后备归队和存读档；额外的隔离剧情离队分支检查召回资格撤销与读档保留。

浏览器共71项检查通过：新手主流程37项、管理专项9项、开发记录7项、已有自动存档/特效9项、音频/档案专项9项。管理专项覆盖四种分组、装备实例保留、真实参战、剧情离队禁止召回与手机布局。人物查看后恢复选择，完整对比状态，区分视图可用性变化与游戏数据变化。

新手主流程保留真实音频播放；只将发生在实际清空音源操作前后2秒内、同一原版媒体URL的`net::ERR_ABORTED`记为预期取消，其余请求失败与HTTP错误继续使测试失败。音频专项另验证真实MP3解码。首次取消请求告警及最终通过记录均保留，不将程序主动释放旧曲目误判为文件缺失。

这批不代表完整通关，正常最终战失败和无悔实时存档缺口继续保留；此前的[90%历史交付](ORIGINAL_90_MILESTONE.md)不是现代化重制的完成度。

## M2实现与平台边界

- `Game.Application.EquipmentComparisonService`是当前GameSession的实例服务，按请求读取最新State；只克隆人物并重建属性，不调用真实装备工厂、随机数或库存变更。支持堆叠装备、独立词条、替换旧装备和新增/失去天赋。
- 浏览器通过独立的类型化只读查询请求对比，不在每次战斗Snapshot中克隆所有装备。界面显示人物面板的前后数值，条件触发和招式专属收益仍以装备说明及实际战斗为准。确认穿戴调用原有使用服务并再次检查条件；过期的界面预览不可直接确认。
- `ItemUseService.DescribeRequirements`与实际使用共用门槛判断，列出全部基础/面板属性、天赋与身份要求，保留原拒绝原因。秘籍页显示总数量、正在分配的人物及空闲数量；满级修炼显示已达上限。
- 修炼总览使用真实人物的主运功法、秘籍、经验和队伍状态，可直接切到该人物的修炼页。仅实际出场者获得战后修炼经验，后备只保留选择。
- 背包查找与排序只作用于视图；输入时只更新结果列表，保留中文输入框及其输入状态，不改变库存顺序。
- 本批建立共用预览服务与明确的查询/展示接口，保留现有存档格式和原始内容数据。培养选择和其他浏览器桥接状态的全面迁移仍属M5，没有宣称整个引擎已完成平台化。

共用换装、库存与物品使用相关38项.NET测试通过；包含新增的无随机数/无库存事件、额外词条、多件装备同序倍率与取整、真实穿戴数值、门槛口径和State替换后服务继续有效检查。堆叠装备使用独立工厂副本预测实际ID，使按来源排序的倍率与真换装一致，同时不占用真实编号。原生管理及双内容包服务回归通过。

本地浏览器58项检查通过：M2专项9项、新手主流程37项、双章节12项。专项验证实际换装与预览数值一致、预览全状态不变、秘籍门槛/分配、修炼总览、背包查找排序、保存恢复和西方内容包复用，并包含375像素布局检查。并发冷启动的初次章节测试超过原20秒预算；初次启动预算改为90秒，其他操作检查保留，完整章节重跑通过。没有据此声称启动性能已优化或完整通关。

## M3首批：手机战斗界面

- 便捷栏在窄屏和较矮的触屏横屏显示，包含走位、选招、行囊、调息和暂停；按钮至少44像素，避让底部安全区。打开面板或结算时隐藏，避免遮挡内容。顶部菜单可横向滚动。
- 选招面板从C#快照读取内力代价、有效距离/范围、冷却、剩余冷却、可用性和拒绝原因。怒气标记为基础代价，奥义等动态变化仍由实际规则结算；不在前端推算伤害。选招只改显示，暂停时可先选招但不自动恢复战斗。
- 原生指针事件逐次记录位移，拒绝超过10像素的拖动、800毫秒以上长按、多指、取消/离开和上下文变化。棋盘保留纵向滚动与缩放。触屏/触笔需再次确认目标；鼠标直接点选。确认前完整状态不变，确认后仍调用同一走位/攻击命令；过期状态不能确认。
- 界面和手势变化不修改原始内容数据、战斗数值及存档格式。当前仍是手动/自动两种控制，没有将便捷栏称作半自动AI，也没有宣称原版战斗完全等价或全路线通关。

验证命令：`npm run test:modern-m3`。浏览器专项使用隔离存档和Chromium真实触摸事件，音频播放在该专项中替换以隔离音频取消请求；真实音频验证属于既有专项。设备模拟不代替Android/iPhone真机与Safari验收。

全新检出需先构建内容和运行时，再从仓库根生成专项所需的隔离存档（不会发放到正式游戏）：

```bash
dotnet run --project src/Game.Web.Runtime/Smoke/Smoke.csproj -- --management src/Game.Web/public/data/content-package.json src/Game.Web/test-results/management-save.json
dotnet run --project src/Game.Web.Runtime/Smoke/Smoke.csproj -- --battle-items src/Game.Web/public/data/content-package.json src/Game.Web/test-results/management-save.json src/Game.Web/test-results/battle-item-save.json
```

然后启动静态服务器，在`src/Game.Web`中设置对应`GAME_WEB_URL`运行上述专项。生成存档及报告留在忽略的`test-results`，不打包进玩家下载。

本地验证：7项手势单元检查、14项触摸专项、37项新手/鼠标操作回归及9项装备修炼专项通过。触摸专项实际施展打鸡血，再验证真实冷却拒绝；拖动、长按、双指、取消和选招均对比完整C#状态。修复旧棋盘容器禁用滚动，以及在pointerup打开窗口后被兼容click立即关掉的问题；在click中消费已验证的点按，不延迟或猜测游戏动作。浏览器控制台及资源请求没有未解释的错误。交付包逐文件校验，72份内容JSON与M2相同。
