# Native runtime checks

Run from the repository root with .NET 10. The native host links the same browser bridge and application services.

Normal gameplay regression, in sequence (output directory is caller-selected and not committed):

```sh
dotnet run --project src/Game.Web.Runtime/Smoke -- --campaign src/Game.Web/public/data/content-package.json /tmp/jyx-campaign new
dotnet run --project src/Game.Web.Runtime/Smoke -- --campaign src/Game.Web/public/data/content-package.json /tmp/jyx-campaign --resume
dotnet run --project src/Game.Web.Runtime/Smoke -- --campaign src/Game.Web/public/data/content-package.json /tmp/jyx-campaign --midgame
dotnet run --project src/Game.Web.Runtime/Smoke -- --campaign src/Game.Web/public/data/content-package.json /tmp/jyx-campaign --chapter2
dotnet run --project src/Game.Web.Runtime/Smoke -- --campaign src/Game.Web/public/data/content-package.json /tmp/jyx-campaign --chapter3
dotnet run --project src/Game.Web.Runtime/Smoke -- --campaign src/Game.Web/public/data/content-package.json /tmp/jyx-campaign --touch-chapter
```

Each stage resumes the previous unedited save. It uses actual creation, visible map actions, source choices, equipment, stat allocation, cultivation, paid training, auto battle and outcome handling. It never edits stats, grants inventory, marks stories complete, directly starts a story/map, or forces a battle result. The initial stage includes 20 browser-authored party practice fights; this is a normal progression check, not a claim that every action comes from the original content. Chance encounters and random rolls can vary. A resolved defeat remains a defeat and follows the original branch.

`normal-save.json`, `normal-report.json` and failure state describe what actually happened. Successful script completion alone does not prove all intended recruits, victories or endgame balance; read the reported party, level and completed stories. The initial observed route reached eight party members, level 22 and three mainline messages. After correcting the character EXP curve, an actual continuation reached 25, the fourth message and four relief victories. The final-battle attempt lost. Full normal progression through Huashan remains outstanding.

`--emergency` continues that checkpoint through real shop sales (three existing gift peaches, spare silver bracelet or dropped golden pestle), two remaining peach uses, earned point allocation, tier-five 4v4 arena fights, then Naxian's emergency story. It uses finite money/medicine and stops on exhaustion; random results need not repeat. The observed continuation required eight additional arena attempts, then won the first Xiangyang encounter. `--xiangyang` follows real Luoyang/Hengyang/Hangzhou relief and the final battlefield; the observed relief battles won and the final battle lost. Its final-victory assertion correctly fails on a loss. Preserve intermediate `relief-*-save.json` checkpoints; do not edit a defeat into a victory.

`--experience CONTENT OLD_SAVE` checks the real pre-fix Lv22/65463 browser checkpoint migrates to Lv22/10253, preserving all other character fields, then checks idempotency, v1 import and invalid-curve atomic rejection. `--story-defeat CONTENT POST_RELIEF_SAVE OUTPUT_SAVE` enters Xiangyang via the actual world event and deliberately rests until defeated. It checks the source's implicit GameOver, no rewards/completion, one death and ending persistence. This is failure routing evidence, not a victory attempt. Browser `test:experience` expects copies of the real old, emergency and game-over exports in test-results as `experience-old-save.json`, `experience-emergency-save.json` and `experience-gameover-save.json`.

The touch stage follows actual Dali/Wuliangshan/Muwanqing prerequisites and the Wan Jie Valley choice, then sends real-time point hits. Its observed score was 117 and the original treatment-success story completed. Optional `--arena-growth` allocates legitimately earned companion points and tries five high-tier arena matches using actual fees, party selection and finite medicine. It preserves losses; completion is a diagnostic checkpoint, not a promise of five battles, victory, adequate funds or balanced bosses. The report records actual results rather than editing them. One earlier attempt found that the separate village temple is no longer reachable by the ordinary map graph after leaving; that was not bypassed or counted as a natural quest.

`--touch CONTENT MANAGEMENT_SAVE NORMAL_SAVE OUTPUT_SAVE` independently checks original source treatment success/failure/next-subject branches. It changes only the normal save's location when preparing the browser temple fixture; this fixture is not a natural journey to that temple. `--battle-return CONTENT MANAGEMENT_SAVE OUTPUT_SAVE` uses actual source arena entry and tier-6 opponents to defeat a low-level character twice and check live same-map retries, recovery and fees. Endgame flow fixtures remain explicitly isolated.

Other checks deliberately use fixtures: `--battle-items CONTENT MANAGEMENT_SAVE OUTPUT_SAVE` grants two actual talent books to a copied inventory, learns them through ItemUseService and recruits Hu Fei via the original reward segment. It then enters the original Yan Ji battle through its real world-map interaction, waits for an enemy-inflicted wound, checks ally healing and exact consumption. Its output feeds the visible browser controls in `npm run test:battle-items`. This is medicine integration evidence, not natural acquisition or whole-route completion. `--achievements` executes isolated original reward segments. `--flow` uses explicit high-stat/endgame prerequisites where documented; it is not normal-growth victory evidence.
