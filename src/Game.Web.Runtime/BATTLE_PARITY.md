# 浏览器战斗与旧版 X 的一致性核对

结论：浏览器正在运行 jyxr 的现代 C# 战斗内核，不能据此宣称已经与原版逐项相同。
手动与自动模式共用实际行动、伤害和结算规则；自动模式改变操作决策，不是另一套伤害算法。

## 核对基线与方法

- 现代规则：`src/Game.Core/Battle`、`src/Game.Application/Battle`，浏览器由 `BrowserBridge.cs` 接入。
- XML 基线：`jyx-legacy-data`，commit `b41198219087858ece19d5484f5061e0289c47bc`。
- 后期 C# 行为参考：`jyx-legacy-dll`，commit `2c62a80de46c48e64e5647511a9c41e088293aff`。
- 官方 Silverlight 是另一较早版本；不同旧版本不作为同一个无差异基准。
- Unity 包目录标为 1.0.0.1，不把它当作已经验证的 1.1.0.6 可执行基准。

此次没有运行旧二进制，也没有实现旧引擎回放。独立验证程序执行现代内核，选取可以从
旧 XML/C# 明确读取的初始数值与规则作为断言。它证明这些选定项目，不证明整个引擎等价。
旧版可能另外执行 Lua 扩展；尚未与整套旧 Lua 组合运行结果逐次对照。

```bash
cd /workspace/jyxr
source /workspace/.cloud-setup-jyxr/env.sh
dotnet run --project src/Game.Web.Runtime/Smoke/Parity/Parity.csproj -- /workspace/jyxr
```

成长规则由 `BattleEngine` 的可选 `skillUseExperienceResolver` 注入，先归一化招式到其
外功/内功，再解析最终经验；未注入时继续使用原有现代成长策略。
验证同时覆盖默认策略 62/62（武学奇才124/124）与金庸策略，原 Godot 宿主无需改用新配置。

草头百姓联动另有 10 项实际施法核对：500/1000 与 501/1000 的边界、攻击及暴击、
攻击者与防御者分别有无草头百姓，以及 20% 以下不重复叠乘。防御侧读取攻击者天赋
是所选旧源码的实际行为，未擅自改成读取防御者。旧内容未指定判断角色时，仍按 Hook
拥有者判断；指定 source/target 的条件可跨角色读取天赋。

## 新增常用规则

人物成长现由 `GameConfig.CharacterExperienceCurve` 选择。金庸浏览器包使用原累计经验，
严格大于门槛才升级；原 `level` setter 会重设经验，单次奖励最多升一级，满级再获经验归零。
默认 PerLevel 策略保留。创建、应用服务、闭关、战斗出招和显示共用所选曲线。
源码及上传 DLL 的具体位置见 [行为证据](LEGACY_INSTRUCTION_EVIDENCE.md)。205 项相关测试
包含硬编码边界、实际施法、成长、结算和存档；另外验证旧网页八人档的逐字段保留及幂等迁移。
原剧情未匹配 `lose` 分支的默认 GameOver 也已接回；明确的失败分支继续按原数据运行。

`legacy_common_rules.py` 显式装配 15 个原天赋和攻击弱化／防御强化。新增对照覆盖
神兵、右臂有伤、左手剑、老江湖、神经病、鲁莽、宝甲、苦命儿、好色与猎人，包含男女／动物
条件的正反例。宝甲→神经病→鲁莽按旧顺序在基础伤害取整后逐次截断，反向学习天赋也不改顺序。
暴躁、斗魂使用现有 Trait；心眼通明阻止致盲但保留中毒，四个测试分别验证有无天赋和两种 Buff。
隔空取物与妙手仁心接入队友用药选择和目标冷却预览；Core 仍裁决范围、天赋和行动资格。
固定／百分比 HP、MP 药发送实际夹限后的恢复事件，供显示正确恢复量。
相关战斗／目标／物品测试 153 项通过；另有浏览器真实伤口治疗及准确扣药验证。

这些是独立公式期望和现代真实执行的比较，没有运行旧二进制作同种子回放。
老江湖单项通过，但它与其他攻击区间变化天赋的组合，仍可能因区间归一化时点不同而产生差异。

## 后续特技与天赋配置

`legacy_advanced_rules.py` 明确装配33项后续天赋和四项状态；原27个特技均已有效果或 Buff 配置。
新增81项实际执行检查覆盖治疗分项取整、火枪基础福缘、解毒的真实友方范围、全队净化、
吴侬眩晕天赋条件、武穆强化、毒系叠加、怪病的平一指保护及嗜酒先后顺序。
嗜酒产生的醉酒当次即可生效；若醉酒已经跳过行动，怪病不再覆盖跳过原因。
秘籍成长另核对六项外功／内功、悟性与武学奇才组合；人物经验不加倍。
243项引擎、加载、天赋及AI相关测试通过，原57项选定规则检查同时保留。

配置审计随构建生成 `data/original-battle-rule-audit.json`，逐项列出原源码引用与已知缺口。
当前仍有93项天赋只含元数据、9项Buff只含元数据，11项特技列为部分配置。
直接伤害的公共管线、天地同寿的永久生命上限代价、追加攻击的负伤害与特殊命中时点等仍待复原。
所有审计条目的完整行为验证标记均为false；上述81项不等于81个完全复原的机制。
隔离施法与浏览器准备档也不算正常剧情获得技能或通关证据。

## 仍存在的差异与优先级

后续组合配置见 `legacy_combination_rules.py`：大小姐／自我主义的人数奖励和逐持有者队伍负面光环、
夫妻同心，以及幽居／素心神剑／左右互搏／醉酒／神速攻击的概率汇总和追加攻击。
新增217项隔离比较包含正反条件、概率边界、三种追加攻击抽样、Buff顺序、人数上限及双天赋去重；
不等于完整随机序列、负伤害回复、死亡反应或特殊技能流程等价。当前64项天赋有配置或部分配置，
93项仍仅元数据，身份声明1项。

| 项目 | 已知差异 | 对新手章的影响 |
| --- | --- | --- |
| 天赋数据装配 | 原转换器仅提取天赋名称、说明、点数，不会把旧硬编码自动转成现代 Affix/Hook。初次核对时 157 个天赋都只有元数据。 | 高：必须逐项为本章实际使用的天赋配置效果，不能把条目数当作实现数。 |
| 其余 Buff 元数据 | Buff 名称、说明、正负分类不等于属性、命中、回合和特殊效果都已装配。Core 内有部分内置状态判断，其余由数据 Affix/Hook 提供。 | 高：本章新出现的中毒等效果需要逐项跑实际效果测试。 |
| 同 tick 行动顺序 | 旧 `BattleField.BattleTimeRun` 按 `_sprites` 顺序入队，并把 SP 上限夹为 100；现代按行动条降序、速度降序、ID 排序，行动后减 100 可保留溢出。 | 中：多人战同 tick 与高速单位连续行动可能不同，首战同速首次我方先动不能证明一般情况。 |
| AI | 旧 `BattleAI.GetAIResult` 可被 Lua 替代，C# 低血有 50% 概率逃开休息。现代按伤害、击杀、友伤、恢复及距离评分。 | 中：同一合法局面不保证做相同决策；自动模式应称现代自动战斗。 |
| 战斗时限 | 金庸包现按旧配置 3000 tick 实施严格大于判负，推进预算在 3001 截停；其他内容包不强加此策略。 | 已测 3000 可行动、3001 失败、双方存活、不发胜利奖励、原失败分支与存档。 |

“初次内容审计”记录补齐前发现的事实。当前只装配了明确列出的首战与常用规则，
不能把这个修复外推为其余天赋和 Buff 已经全面复原。

## 当前不能宣称等价的部分

- **伤害与命中全量**：基础攻防公式相似，但还没有将全部技能、招式、内功、装备词条、
  Buff 和天赋组合对旧引擎逐次验证。首战测试只覆盖初始模板，不外推至完整武学库。
- **技能、天赋和奥义**：158 门外功、43 门内功、137 条奥义等属于已加载定义数。
  触发条件、专属 Hook、免疫、反制、死亡阻止和伤害顺序仍须按实际行为验收。
  仓库 `TODO.md` 明确记录血刀大法/吸招式固有吸血尚缺；直接伤害会绕过部分公共管线；
  部分附加伤害、八卦阵转移、受击回怒等保留了当前实现取舍。
- **AI 对复杂技能的评价**：`TODO.md` 明确指出全场 selector 和 Buff/控制收益尚未进入
  完整真实目标与收益评分，自动战斗不能视为原版 AI 的还原。
- **药品**：现有 Core 已支持战斗内目标、实际扣除和冷却。尚未完成所有药品、队友范围、
  禁药/免冷却天赋与多人边界对照，也没有让 AI 自动选择背包药品。
- **结算与掉落**：普通胜利通过真实 `BattleService` 结算，随机装备词条已参考旧顺序试投。
  但未校准所有旧 Lua 的掉率配置、残章、高周目、特殊战奖励与 `bonus=false` 条件。
  少量实战胜利不足以证明随机分布一致。
- **随机性**：当前执行使用 `Random.Shared` 等多个路径，不共享旧引擎的随机种子、调用序列。
  不能要求同一存档下每击、暴击、掉落完全相同。未来对照应向执行路径注入可记录随机源，
  记录决策输入、随机抽样及结构化结果，再比较规则；不用“打赢了”代替公式验证。
- **原版操作与表现**：原版图片／角色帧由现代网页 UI、自动/暂停/倍速表现层驱动；棋盘战术玩法可复原，
  不宣称 Unity 原界面、动画时序和音效逐帧相同。

本章验收应优先保证：角色基础数值、用到的天赋/Buff/技能、走位与用药、伙伴归属、
胜负回写、经验/奖励及存档一致；随后逐项扩大规则矩阵。未用到的后期武学保持“未验证”。
