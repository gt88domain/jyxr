# 现代宿主的中期流程验证

本批继续使用 `content/jyx/assets.json` 锁定的原版数据与素材，1,272 个文件逐项校验。没有调整剧情、技能、道具数值、加入条件或战斗胜负。网页显示与交互仍由现代宿主管理，规则由共用 C# 会话执行。

## 本批行为

- 未完成的教学任务优先显示；入门体验目标完成不会掩盖教学任务。
- 后续主线消息显示当前等级、参战人数及原条件。“已收到消息”不代表对应剧情全部完成，后续行动仍需查看记事和相关人物。
- 任务面板可直接打开当前地图的伙伴招募线索，保留原条件与只读浏览。该功能由内容模块能力控制，西方模块不加载金庸资料。
- 中期人物状态不再标作“旅程初始”，地图标题也不再固定称作教学阶段。

## 实际验证与边界

本地 `midgame-modern-final.json` 通过 18 项检查，`modern-jyx-regression.json` 通过 29 项新手回归。测试使用独立浏览器上下文，不覆盖玩家存档。

中期检查从真实成长存档出发，通过地图按钮、交谈和原版选择完成令狐冲加入，再招募蓝凤凰并获得原版奖励“毒龙鞭法秘籍”。随后验证伙伴装备对比与确认、秘籍修炼、暂离归队与排序、存读档后装备实例保持一致、真实战斗中的修炼经验增长，以及旅馆仓库存取。8 人队伍实际触发“神秘剑客_战斗”并获胜。375 和 320 像素宽度的地图、队伍、修炼和任务面板均无横向溢出。

这里没有宣称全路线通关。原生驱动的不同实际运行中，曾出现后续剧情完成、分支战败及主线条件未满足三种结果。最终浏览器检查中的“神秘剑客”战斗获胜，没有覆盖该战斗败北后读档的分支。最后一份原生后期断点只有 7 名参战成员，因此“神秘剑客5”“组织1”仍未完成，报告明确列为 `notCompleted`；断点文件名 `chapter2.json` 仅标识准备阶段。

## 容易误判的原版条件

| 内容 | 条件或含义 |
| --- | --- |
| 大地图帐篷的早期郭靖入口 | 郭靖及松鼠郭靖均不在队，尚未完成“黑暗的阴影1”，并通过 50% 概率；错过不能用队伍管理强行补入 |
| 令狐冲加入 | 华山后山入口，原版道德区间为 35 ≤ 道德 < 65 |
| 蓝凤凰加入 | 保留原版令狐冲前置及对应交谈，奖励来自剧情 |
| 黑暗的阴影消息 | 主角 10 级、参战队伍 4 人 |
| 神秘剑客消息 | 主角 15 级、参战队伍 8 人，完成“黑暗的阴影1” |
| 组织消息 | 主角 22 级、参战队伍 8 人，完成“神秘剑客1” |
| 紧急消息 | 主角 25 级、参战队伍 8 人，完成“组织” |

消息条件来自现有内容；`friend_count` 对应当前参战队伍人数，包含主角，不包含暂离成员。队伍只有 7 人时，即使等级已够也不会收到要求 8 人的消息。

## 重跑

在 `src/Game.Web` 安装依赖、构建金庸模块并启动静态服务后：

```bash
# .NET SDK 必须已在 PATH 或 DOTNET_ROOT 中。
npm run prepare:midgame
GAME_WEB_URL=http://127.0.0.1:4212 npm test
GAME_WEB_URL=http://127.0.0.1:4212 npm run test:midgame
```

准备结果与 SHA-256 来源记录位于忽略提交的 `test-results/midgame/`。准备脚本接受正常成长造成的队伍差异，保留实际状态；若出现原版致死失败，记录失败与最后可保存断点。浏览器检查依据本次来源记录读取断点，通过可见界面完成操作，不直接发放奖励、改写数值或伪造胜利。运行较长，可用 `GAME_WEB_REPORT` 为报告指定独立名称。
