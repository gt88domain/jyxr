## 统计口径

冻结的原包包含 513 个角色定义、413 种显示名。按有依据的身份合并成长形态后，对照表包含 417 组实体：308 组剧情人物、86 组兵种／动物等通用模板、22 组系统对象和 1 组玩家。不是 513 名可招募伙伴。

剧情人物中，25 组核心身份固定，283 组为待审候选。候选库列出 474 名既有人物，当前命名原创角色为 0。招募目录覆盖 65 个原定义形态、63 种显示名、62 组身份；这是当前目录的引用覆盖，不声称所有剧情条件已经可达。

身份合并依靠原编号、已知别名和剧情证据，不能只看显示名：

- 阿九拜师获法号九难，原剧情的离队／入队命令也相互对应，因此保留两个定义、共用一组身份。
- 长安深夜的三种神秘女子形态后来揭名霓裳，共用身份；另一个名为练霓裳的定义不凭名字相似强行合并。
- 温家五兄弟的原显示名有重复，五个定义仍是五个人。
- 不同的蒙面人、神秘人不会因通用名称相同而合并。

证据入口和具体原剧情编号记录于 content/worlds/identity-notes.json。每个原定义保留完整定义的 SHA-256，用于检查基础规则是否被误改。

## 选角与审阅

先找适合该国主题、剧情位置和战斗形象的知名文学、传说或历史人物。确实没有合适既有人物才使用命名原创，必须记录真实缺口原因。普通士兵、动物和物件是模板，不伪装成命名原创角色。

已固定身份不能被脚本自动重新分配。待审候选不表示剧情、性别、关系和能力已经适配；表中分别提示叙事与战斗适配、形象调整和地域知名度等问题。知名度分为广泛／类型受众／地域受众，只是编辑估计，不是调查排名。

来源列区分原始作品、神话、民间传说与历史。选取基础人物不等于可以使用任何现代影视形象、译文或美术；后续素材需要逐项记录来源。这里没有使用现代改编电影的图片。

## 数据与工具

数据位于 src/Game.Web/content/worlds：

- project.json、countries.json：项目阶段、备份、国家主题结构与设计边界。
- figures.tsv、figures.json、source-labels.json：既有人物库、双语姓名与来源标签。
- cast-map.json：持久化角色身份、国家、候选状态、原定义形态与摘要。
- legacy-index.json：所有 513 个原定义到身份的索引。
- locked-identities.json：25 组固定身份注册表。
- identity-notes.json：别名与合并证据。
- grimm-skin.json：按原对白槽位替换的双语开场，角色编号仍为南贤；真实游戏入口 game/，中文文案通过 lang=zh-CN 查看。
- manifest.json：同一 jyx 游戏的显示覆盖模块，使用独立存储和版本；原数据与本地格林头像均校验 SHA-256。

seed-world-cast.py 只用于首次建立草案，不是普通构建步骤；不得通过重跑种子脚本洗掉人工审阅。正常构建只读取已经保存的映射。相关国家由原剧情说话人、命令参数和战斗引用推导，尚不等同完整条件求值或路线可达性分析。

在 src/Game.Web 运行：

完整构建步骤见 README；角色站点构建会从 dist 合入真实游戏。角色浏览器检查可用 WORLD_CAST_URL 指向站点根目录；真实游戏检查用 GAME_WEB_URL 指向 game/。构建还生成逐文件核验的 artifacts/fantasy-worlds-cast.zip。

双语页面支持国家、原名／新名搜索、可招募引用、固定／待审筛选、成长形态详情和 CSV／JSON 导出。中英切换保留筛选和身份。手机首屏保留主要搜索和首个人物，不常用说明收在展开区。审阅工具不读写旧游戏存档，也不创建游戏数据库。英文页面保留原中文编号以便核对，这不表示原对白已翻译。

## 格林求助的开场

开场用六句交代格林收集各国陪伴人们长大的童话，故事失序，因此召唤玩家帮忙。游戏暂名童话旅人 / Storybound，不在开场强调国家数量。格林始终是主要引导者，其他著名作家可作未来彩蛋。原南贤的位置、编号、询问选项、跳转、修炼书奖励和原首战流程保留；开场由 23 句压到 6 句，小村说明由 6 句压到 2 句。

dialogueEdits 只替换经校验的连续纯对白段落。构建比较非对白节点，保护原命令、条件、奖励和跳转的顺序；不以保留旧句数为目标，也不通过隐藏空白对白凑数。

模块身份 worlds、存储 jyxr-fantasy-worlds 与原版隔离，但运行态 packId 保留 jyx。因为宿主按该身份选择原版累计经验、教学任务与战斗规则，不能为了换题材把这些规则改变。中英显示包分别在 packs/worlds/en 和 packs/worlds/zh-CN，内容索引仍指向同一原始规则身份；条件、人物、物品、地图和存档内编号不变。

已经撤下独立开场阅读器。旧 opening/ 链接转到 game/ 并保留语言参数；旧实现仍可在 Git 历史 355e460 中找到。现阶段实际运行的是原游戏，装备、修炼、战斗、奖励和存档均由同一个宿主执行。后续仍有未替换的原版人物、地名与中文界面，不能称为完整英文版或完整内容改写。

战斗、装备、修炼与存档继续复用现代宿主，玩法数值不因换名字而改变。完整国家章节需要单独验证入口、奖励、招募和回档；本次角色工具的检查不能代替完整游戏验证。

## 文案与流程审阅

`review/` 是只读编辑审阅页，与真实游戏 `game/` 分工独立。它并排显示原版中文、新版中文与新版英文，支持全文搜索、类别、剧情编号、已接入／待改写筛选，以及文案与流程之间的跳转。手机将三列依次排列，常用搜索和范围筛选保留在首屏。

`scripts/world_review.py` 从冻结原包和实际格林覆盖生成审阅数据。原包含 1,887 段剧情、8,577 句对白；连续纯对白合为一个对照单元，保持 23 句改成 6 句的真实对应。原文未变化时新版栏留空并标待改写；候选人物单独显示，不算已接入改写。提取范围包括包内对白、选项、日志、提示，以及人物、技能、物品、地图等定义的显示字段；界面源代码内的文字不在此范围。

- `review/data/copy.csv`：原文、新中文、新英文、状态、备注、候选人物、来源路径和稳定行号。
- `review/data/flow.csv`：分支条件、选项选择、战斗胜负、原命令、物品引用、入队与跳转；也收录地图事件、全局触发、拜师入口与宿主任务／伙伴引用。
- JSON 文件保存相同资料；`manifest.json` 记录来源 SHA-256、统计及缺失目标引用。

稳定行号从冻结原包路径生成，修改新文案不会改变原行身份。CSV 带 UTF-8 BOM，保留引号和多行，并转义可能被表格解释为公式的单元格。CSV 当前仅供下载编辑，尚无自动回填或直接发布功能；条件、奖励和编号不作为自由改写栏。所有入口与分支都是静态引用，局部条件不等于完整可达条件，未执行路线或通关验证。

在 `src/Game.Web` 运行 `npm run review:export` 单独导出到 `artifacts/world-review`；`npm run cast:build` 会将审阅页和资料合入站点。已有 worlds 的 `dist` 可直接用于这一步，无须重编译未修改的游戏运行时。校验用 `python3 -m unittest discover -s tests -p test_world_review.py`；浏览器检查用 `WORLD_REVIEW_URL=http://127.0.0.1:4220/review/ node tests/world-review-smoke.mjs`。
