# 模块化现代游戏：西方试验章

原版备份固定在 `html5-web` / `e5bcf716591569bfea4747a8b3b6f4c8a91f5e1c`。本分支是其现代规则与服务的延续；不在旧分支修改，也不把两种题材各复制一套战斗内核。

| 模块 | 所在位置 | 职责 |
| --- | --- | --- |
| 规则 | `src/Game.Core` | 伤害、目标、天赋/状态、AI、成长；不依赖网页或Godot |
| 会话与用例 | `src/Game.Application` | 队伍、背包、装备、交易、修炼与存档 |
| 内容装配 | `src/Game.Content` | 定义加载、引用解析与校验 |
| 浏览器适配 | `src/Game.Web.Runtime` | C# WebAssembly导出、指令契约与每个世界的独立会话 |
| 西方内容 | `src/Game.Web/content/frontier` | 清单、地图、剧情、人物、道具、战技及术语 |
| 界面 | `src/Game.Web/src/ui` 及其他视图文件 | 导航、人物、对话、战场、触屏操作；不自行计算伤害 |
| 浏览器存储 | `src/Game.Web/src/app-config.ts`、`storage.ts` | 应用命名空间，再按内容包保存进度和档案 |

`main.ts`继续负责交互协调，公共格式、图标和界面外框已拆入 `ui/format.ts`、`ui/shell.ts`。桥接层仍较大，尚不是完整插件系统；旧规则适配代码仍保留在源码中，但西方启动不加载原版内容或调用原版剧情。以后拆分桥接用例时沿用现有会话和契约，不建立第二套全局状态。

## 独立内容构建

`scripts/build-frontier.py`只读取本模块和清单中的4张原创图片，不初始化原版数据或DLL参考子模块。清单记录稳定包ID、版本、资源SHA-256和来源；C#正常加载器在进入游戏前继续验证真实跨表引用与剧情指令。`vite.config.ts`只复制本模块需要的静态文件，不把原版资料与素材带入发布目录。

本章沿用既有试验内容：一个营地、一段野外旧道、一座废塔、两个真实战斗和一次委托结算。修复了拒绝招募后消耗一次性入口的问题：玩家可改变主意，加入后仍由在队条件切换成后续对白，不会重复生成伙伴。关卡入口仍要求先完成路障并带上玛拉。

## 存档与备份

旧版使用 `jyxr-web` 数据库和 `jyxr.preferences.v1` 设置；新版使用 `jyxr-modern-western` 和 `jyxr-modern-western.preferences.v1`。旧存储不会自动读写，旧版根网址保持不动。明确导入同内容包的v2存档仍通过原有校验，原版v1/不同包存档不会替换西方会话。

## 验证与边界

从新游戏出发检查开场奖励、拒绝/重新招募、换装、修炼、真实交易、手动走位、自动战斗、两次胜利、账册、一次性报酬、存档/导出/刷新和手机布局；不修改玩家属性、不强制胜利。另有C#正常加载、拒绝坏包、错误存档与招募回归。

这证明一个小章可以在共用引擎上运行，不代表全平台、长时间游戏或未来内容都无Bug。当前角色共用一张佣兵图、独立音频尚未制作、战技种类少；复杂战斗规则与桥接用例的进一步拆分按实际缺陷逐批推进。保留GPL及原作者署名，生成素材来源见 `src/Game.Web/public/art/README.md`。
