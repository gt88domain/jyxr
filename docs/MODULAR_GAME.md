## 一套管线

`build-game.mjs`依次运行契约、内容、WASM、类型检查和前端构建，给各阶段传递同一个`GAME_MODULE`。默认`jyx`，`build:frontier`显式选择`frontier`。Vite读取对应模块清单，注入应用配置，只复制选定模块的资源。`main.ts`不决定题材数据或数据库名称。

`content_modules.py`统一校验模块标识、资源路径、字节数和SHA-256。金庸模块直接采用冻结发布提交中的运行JSON，保持全部原字节。西方模块调用自己的创作入口生成JSON，之后同样由真实C#内容装配器解析。没有初始化旧数据/DLL子模块也能重建这两种运行包。

金庸清单共1,272个文件：70个JSON、2个配套文字资料、1,196个素材/说明、4个署名文件。旧索引中两包混装的设置被独立金庸索引替代；西方运行包和4张西方图片不进入金庸发布目录。地图、剧情、技能、装备、人物和资源映射不修改，原有缺件与浏览器教学适配继续保留原记录。

如未来确需重新迁移原资料，`build-content.py`是历史迁移工具；它不是默认构建步骤。应另行准备来源、审查数据差异，再显式更新基线清单，不能以重建宿主为由重算或混合不同版本的数值。

## 验证和剩余边界

先验证完整数据引用，再从新游戏实际进行问答、出生、南贤剧情、木人战斗、教学奖励、洛阳交易、穿装备、钟灵招募、双人练习、修炼成长、章节回顾与存读档。伙伴图鉴与资料馆必须只读；320和375px面板保持可操作。用隔离浏览器的旧版/西方存储标记检查命名空间不串写。

此次是宿主迁移验证，不是完整金庸世界的通关证明。长线剧情、更多队友条件和复杂战斗组合仍需逐路线检查。`BrowserBridge`与`main.ts`仍较大；后续应逐用例拆分，在保持当前会话和契约的前提下推进，不能另建一套全局状态。当前也不是任意旧MOD代码都能直接加载的插件平台。
