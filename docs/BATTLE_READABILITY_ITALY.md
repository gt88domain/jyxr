# 战场可读性与意大利终战检查

本批基于 `b7913959845a95880fcf13103331c8e87eda31c6`，在 `feat/storybound-italian-battle` 继续。没有修改战斗规则、数值、人物成长、奖励或剧情判定。

## 界面

窄格使用 `#1` 等编号；桌面显示编号与按格宽截短的名字。展开棋盘下方参战名单，可按相同编号查看完整姓名、血量、退场状态与当前行动者。同名守卫可以区分，完整姓名不会被删去。名单默认折叠，打开名单不派发游戏命令。

缩放时画布可能短暂隐藏或尺寸不足，旧绘制会向 Canvas 传入负半径。本批跳过不足以绘制的瞬时尺寸，恢复正常大小后照常绘制；仅影响画面布局。

`battle-labels-smoke.mjs` 从已发布、未编辑的法国决战前存档通过地图与对白进入实际战斗，检查16个编号与完整姓名，并在320、390、1440px验证布局及查看名单前后战斗状态不变。`PLAYTHROUGH_CHECKPOINTS` 指向已发布存档目录，必须通过清单SHA验证。浏览器截图为 `src/Game.Web/test-results/battle-labels-mobile.png`。

## 意大利普通难度

使用已发布的 `italy-trained.json`，从真实48次练习后的存档继续，通过实际地图、对白、原选项与4倍速自动战斗操作。两场开场战斗获胜，最终主角对奥兰多和六名守卫时失败。浏览器没有游戏异常。该试跑不手动使用药剂，因此不代表最优打法，也不能据此判定需要削弱敌人。

存档主角13级，但已学主动战技只有10级基础拳术，主专精为11级基础专精；剑术45，奖励剑术手册要求剑术60、定力50。反复进行低级练习没有自动补足武器体系和教材要求，不能将等级上升或拥有教材视为培养完成。

这里的10级基础拳术按原定义已有威力跃升，不能仅凭“基础”名称判定它弱。后续手动试跑使用同一存档、实际走位与选招并消耗17瓶既有回复药，仍在单人终战失败。两场开场战后主角能量分别余416、201，终战失败时余144；连续战斗的能量与药剂管理是需要进一步验证的因素，不把一次策略失败说成核心故障。

下一次准备试跑从同一个完整战前存档出发，通过研习面板选择背包已有、拳套条件可满足的 Petalstorm Fist Manual，并优先清理较低血量目标；没有写入技能、装备或属性测试值。相关入口为 `ITALY_PREPARE=1 ... node src/Game.Web/tests/italy-manual-smoke.mjs`，实际结果以 `italy-prepared.json` 为准。

该准备试跑也已完成：两场开场战获胜，主角能量余718、70；终战仍失败，余11能量，实际消耗17瓶既有回复药。只更换一本可学教材与目标顺序，没有得到通关结果。下一步应实际走商店购买可负担的能量补给，或建立更完整的防御与续航培养路线，再验证；不能将目前策略失败视为正常路线不可通过。

新增英文提示说明自动战斗不会替玩家管理药剂，并补齐此战 `精兵铁卫` 的显示别名 Castle Guard，沿用人物表已分类的城堡卫兵身份。内部人物编号、原名与属性保留。实际生成词典的显示投影检查通过；不将这项静态显示检查说成又打通了一次终战。

战前指引补充检查已学战技、主专精、装备及手册条件，不新增任务门槛。下一步应从真实可获得的教材和属性培养中形成有效的主角单人构筑，再验证终战；目前不宣称匹诺曹已经招募或意大利线已通关。

测试入口 `italy-observed-smoke.mjs` 另检查落败记录的保存、读取，以及导入完整战前档恢复重试前提。真实结果保存在 `src/Game.Web/test-results/italy-observed.json`；其中 `passed` 表示验证流程通过，最终胜败须读 `outcomes`，不能当作通关标志。
