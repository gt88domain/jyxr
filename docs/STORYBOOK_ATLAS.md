# Storybook atlas

The fantasy preview now uses an original illustrated island map instead of the old mainland illustration and Chinese building icons on the world travel screen. Select an island to filter destinations, search across all islands, or show places without a current event. Only a destination button sends the existing `interact` command. Island selection, searching and filtering are free UI operations: they never advance time, grant items or change state.

`src/Game.Web/content/worlds/world-atlas.json` contains bilingual presentation metadata for all 71 native world-map destinations. Six geographic groups organize the view; they do not introduce six story routes or settle the planned country/character assignments. Their percentages position region buttons on the illustration, independently of the original coordinates used to calculate travel. Every native destination appears exactly once; content compilation rejects missing, duplicated or invented destinations and invalid art paths or region coordinates.

Available destinations appear first. Places without a current event are hidden initially and can be shown as disabled entries. Availability comes directly from the host, including unfinished prerequisites and already consumed events. The interface does not assume that an unavailable destination is unfinished development. Each enabled destination displays the host's actual travel-and-interaction time. Browser save data does not contain map filters.

The native opening guide precedes the atlas, rather than following the entire destination list. Its currently actionable world-map hop is labeled **Next stop** and sorted first; unavailable events never gain a recommendation or become clickable. Search and region controls precede the illustration. **Browse destinations** folds the illustration and moves keyboard focus to the results; the map can be expanded again. Search accepts accents and either apostrophe style and matches words in any order. Entering another map restores the top of the view so the task heading does not disappear above an inherited scroll position. These operations only affect the view and do not write to saves or dispatch host commands.
